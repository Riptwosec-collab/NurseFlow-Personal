# NurseFlow Personal v0.7 — Supabase cloud backup

- **Web UI**: 402px iPhone frame on desktop; full phone width on iPhone; white/pastel, Thai/English.
- **Local first**: the existing localStorage key `nurseflow-personal-v1` is unchanged. Offline use does not require a Supabase account.
- **Opt-in cloud**: Settings → Supabase Cloud → create account/sign in → Upload backup to seed the cloud → optionally toggle Auto Sync. Another device signs into the same email account and chooses Restore backup. There is **no automatic upload/overwrite at first sign-in**.
- **Recovery**: Restore makes an IndexedDB recovery point before replacing the local schedule. If IndexedDB is blocked, restoring still requires explicit confirmation; export JSON for another independent copy.
- **Conflict prevention**: each user has one cloud backup row with integer revision. Updates use the previous revision as a PostgREST filter; if another device changed the row, Auto Sync pauses instead of overwriting it. An explicit *Replace cloud* action can override after a confirmation.
- **Security**: `public.nurseflow_user_backups` is RLS-protected by `auth.uid()` and is only accessible to authenticated users with row ownership. Only the `sb_publishable_...` key goes to the browser; **do not** add service-role or secret keys. The data is **plain JSON in Supabase Postgres**, not end-to-end encrypted. Do not put patient-identifying or medical record data in notes.
- **Authentication**: Supabase email/password signup and sign-in. If email confirmation is enabled, confirm from your inbox, then return to NurseFlow and sign in. In Supabase Dashboard → Authentication → URL Configuration, add `https://nurseflow-personal.vercel.app/` to the Redirect URL allowlist so confirmation links can return to this app. Existing Supabase users can sign in directly.
- **Database**: isolated table and RLS policies created by the Supabase migration `nurseflow_personal_user_backups_v1`, on project `gfqkexnqbjtuwsyqacsw`, Singapore region. The database hosts other apps too; no unrelated tables were touched.
- **Legacy**: the previous *Cloudflare Worker/D1* code is not used by the new Supabase UI. Old cloud settings are not deleted and the historical backend remains in the repository, but the app no longer offers Cloudflare setup buttons.
- **Tests**: Node syntax checks, Chromium responsive smoke tests (320/375/402/1440 CSS px), mocked Supabase Auth + PostgREST backup and revision tests. Live user-signup/sync cannot be verified without the user signing into their account; simulated tests do not prove email-delivery or end-to-end sync on iPhone Safari.
